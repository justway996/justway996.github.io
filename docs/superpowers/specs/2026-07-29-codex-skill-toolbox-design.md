# Codex Skill Toolbox — 第一版设计

## 目标

为不懂 Skill 的普通用户提供一个可安装的 Windows 桌面工具箱。用户按职业和任务使用 Codex；应用在后台发现、解释、安装和管理本机 Skill 及其依赖。

首个可用职业工具箱为“道具设计师”。客户也可以创建、导入、测试和分享自己的 Codex 小工具。

## 用户与边界

### 目标用户

- 不理解 Skill、插件、MCP、配置文件或依赖关系的职业用户。
- 有意把自己制作的 Codex 小工具分享给他人的高级用户或行业专家。

### 第一版不做

- 云端账号、团队协作、在线市场或远程执行。
- 静默安装、静默更新或绕过 Codex、操作系统和第三方服务权限。
- 自动修复任意第三方 Skill 的代码。

## 产品形态

独立 Windows 桌面应用，安装于任意电脑。本机的 Codex 是执行引擎；应用通过读取其公开的本地配置、Skill/插件目录和命令行可用性来建立能力目录。

应用不要求用户理解 Codex 内部结构。默认界面只显示职业工具和任务，高级页才显示 Skill、插件、MCP、来源和依赖图。

## 信息架构

### 职业工具箱

展示职业卡片、每个职业包含的业务工具、所需能力和安装状态。

第一版的“道具设计师工具箱”包含：

1. 灵感与风格研究：把主题、时代、角色、受众和预算转为研究方向与参考清单。
2. 道具概念设定：生成概念说明、图像提示词、尺寸和细节设定。
3. 材料与工艺建议：按使用场景、预算和耐用性给出材料、表面处理与制作建议。
4. 制作清单与预算：生成 BOM、工时、风险与采购建议，并支持表格或 PDF 交付。
5. 客户提案包：整理方案逻辑、参考素材、预算和交付内容，生成可编辑演示文稿或 PDF。

每个业务工具映射到一个主 Skill，以及零个或多个可选依赖。例如“客户提案包”可能依赖文档、演示文稿、表格和 PDF 相关能力；用户只看到一个业务工具。

### 我的自定义工具

提供四个入口：

- 新建：用户填写用途、目标职业和输入/输出；Codex 辅助生成最小 Skill 模板。
- 导入：接受本地 Skill/插件目录或 ZIP 包。
- 测试：显示解析结果，在用户确认后运行一条受控测试任务。
- 导出：打包当前工具和清单，供另一台电脑导入。

自定义工具默认处于“已发现、未启用”状态。只有通过结构校验、依赖解析和用户确认后，才会写入 Codex 的可发现范围。

### 本机能力扫描

首次启动及用户手动触发时，扫描器执行：

1. 检查 Codex 是否存在且可调用；不存在时提供安装说明，不代替用户安装。
2. 发现全局、项目级和已安装插件带来的 Skills。
3. 读取名称、描述、路径、来源、版本（如有）和支持文件。
4. 标记同名项的优先级、生效版本、重复项和禁用/缺失项。
5. 对职业工具和自定义工具计算依赖状态：已满足、缺失、冲突或需要授权。

扫描默认只读。安装、启用、导入和删除必须由用户明确触发。

## 核心交互流程

```text
首次启动
  -> 扫描本机 Codex 环境
  -> 显示可用能力与缺失前置条件
  -> 选择职业工具箱（默认展示道具设计师）
  -> 选择业务任务
  -> 预检依赖与权限
  -> 用户确认安装/启用
  -> 调用本机 Codex 执行
  -> 展示进度、产物路径和失败建议
```

导入自定义工具：

```text
选择文件夹或 ZIP
  -> 解包到应用管理的隔离区
  -> 校验结构和清单
  -> 扫描声明依赖、脚本和权限提示
  -> 显示预览与冲突
  -> 用户确认启用
  -> 写入或链接到目标 Codex 范围
```

## 依赖和安全模型

工具包使用一个显式清单记录：工具 ID、版本、主 Skill、依赖项、来源、最低 Codex 要求、可选外部服务以及风险标签。

风险标签至少包括：联网、读取工作区、写入工作区、执行命令、外部账号访问。第一版只展示和确认这些标签；不声称能够完整审计任意第三方脚本。

安装前必须显示：将添加的项目、写入位置、来源、版本、已解析依赖和权限风险。每次从未信任来源导入时，用户必须再次确认。

回滚通过保存每次变更前的工具箱清单和受管理副本实现。第一版只回滚由本应用管理的内容，不改动用户已有的原始文件。

## 分享格式

导出的分享包采用 ZIP，包含：

- `toolbox.json`：工具箱元数据、版本与依赖声明。
- `tools/`：自定义 Skill 或插件的源文件。
- `README.md`：业务用途、安装说明、风险说明和支持范围。

导入时不自动执行包内脚本；脚本是否可运行由结构校验和用户确认决定。

## 第一版技术划分

- 桌面壳：提供安装、职业工具箱和高级管理界面。
- 本地发现器：只读扫描 Codex 可发现位置和应用自管目录。
- 工具清单服务：维护职业工具到 Skill 依赖的映射与状态。
- 导入/导出服务：校验、隔离、打包和受管理安装。
- Codex 适配器：检查本机 Codex、构造任务调用并收集执行结果。

这些模块仅通过清晰的数据模型通信；扫描器不负责安装，导入器不负责执行任务，Codex 适配器不决定业务工具的依赖。

## 验收标准

1. 在未安装 Codex、已安装但无 Skill、以及已有多个 Skill 的电脑上，应用能给出准确的状态和下一步。
2. 道具设计师工具箱的五项业务工具均能显示用途、依赖和状态。
3. 用户能导入一个合法 Skill 或插件目录/ZIP，看到依赖预检后再决定是否启用。
4. 用户能导出一个自定义工具并在另一台电脑导入；导入后仍经过预检与确认。
5. 重复或被覆盖的本地 Skill 在高级页清楚标示，不会被应用静默删除或改写。
6. 所有会写入、联网、执行命令或访问外部账号的操作均有明确提示和用户确认。

## 验证策略

- 为路径发现、清单解析、依赖解析和 ZIP 校验编写单元测试。
- 用临时目录模拟无 Codex、单层 Skill、同名覆盖、缺失依赖和损坏 ZIP。
- 人工验收安装后首启、职业工具展示、导入预检、启用确认和导出再导入。
