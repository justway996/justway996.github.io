# Codex Skill Toolbox — 第一版设计

## 目标

为不懂 Skill 的普通用户提供一个可安装的 Windows 桌面工具箱。用户按职业和任务使用 Codex；应用在后台发现、解释、安装和管理本机 Skill 及其依赖。

首个可用职业工具箱为“道具设计师”。客户也可以创建、导入、测试和分享自己的 Codex 小工具。

## 用户与边界

### 目标用户

- 不理解 Skill、插件、MCP、配置文件或依赖关系的职业用户。
- 有意把自己制作的 Codex 小工具分享给他人的高级用户或行业专家。

### 第一版不做

- 云端账号、团队协作、在线市场或远程执行。
- 静默安装、静默更新或绕过 Codex、操作系统和第三方服务权限。
- 自动修复任意第三方 Skill 的代码。

## 产品形态

独立 Windows 桌面应用，安装于任意电脑。本机的 Codex 是执行引擎；应用通过读取其公开的本地配置、Skill/插件目录和命令行可用性来建立能力目录。

应用不要求用户理解 Codex 内部结构。默认界面只显示职业工具和任务，高级页才显示 Skill、插件、MCP、来源和依赖图。

## 信息架构

### 职业工具箱

展示职业卡片、每个职业包含的业务工具、所需能力和安装状态。

第一版的“道具设计师工具箱”包含：

1. 灵感与风格研究：把主题、时代、角色、受众和预算转为研究方向与参考清单。
2. 道具概念设定：生成概念说明、图像提示词、尺寸和细节设定。
3. 材料与工艺建议：按使用场景、预算和耐用性给出材料、表面处理与制作建议。
4. 制作清单与预算：生成 BOM、工时、风险与采购建议，并支持表格或 PDF 交付。
5. 客户提案包：整理方案逻辑、参考素材、预算和交付内容，生成可编辑演示文稿或 PDF。

每个业务工具映射到一个主 Skill，以及零个或多个可选依赖。例如“客户提案包”可能依赖文档、演示文稿、表格和 PDF 相关能力；用户只看到一个业务工具。

### 我的自定义工具

提供四个入口：

- 新建：用户填写用途、目标职业和输入/输出；Codex 辅助生成最小 Skill 模板。
- 导入：接受本地 Skill/插件目录或 ZIP 包。
- 测试：显示解析结果，在用户确认后运行一条受控测试任务。
- 导出：打包当前工具和清单，供另一台电脑导入。

自定义工具默认处于“已发现、未启用”状态。只有通过结构校验、依赖解析和用户确认后，才会写入 Codex 的可发现范围。

### 搜索与智能推荐

首页提供任务搜索，而不是要求用户搜索 Skill。用户可以输入“做 PPT”“给客户做道具提案”或“把表格做成图表”。

搜索服务把用户的任务映射为一个或多个“执行方案”。每个方案由一个主 Skill 和经过验证的依赖组合组成，并显示：

- 推荐名称，例如“客户提案 PPT”。
- 能完成的工作、预计产物和适用场景。
- 推荐原因，例如“已安装全部依赖”“与你的道具设计师工具箱匹配”。
- 安装状态：立即可用、需要安装、需要授权或存在冲突。
- 所需 Skill 的数量和名称，仅在“查看详情”中展开。

默认只展示一条“推荐方案”和至多两条替代方案；不把所有匹配到的 Skill 直接抛给普通用户。

“做 PPT”的首选方案应优先使用已安装、来源可信且兼容的演示文稿能力。若缺失依赖，界面明确显示将安装哪些能力和为什么；用户确认后才安装。若检测到同类 Skill 冲突，推荐一个可运行的组合，并把另一个组合标记为“未选用”，而不自动删除任何内容。

### 冲突解决向导

当任务搜索、导入、安装或运行前检查发现冲突时，普通用户不需要编辑配置文件。应用以“修复此工具”方式启动向导，展示：冲突的业务影响、系统推荐方案、将要变更的项目、可恢复点和替代方案。

第一版可处理以下确定性冲突：

1. 同名 Skill 被更高优先级位置的版本覆盖。
2. 工作流声明的版本与本机受管理版本不一致。
3. 已知互斥的 Skill、插件或外部服务组合。
4. 依赖缺失、被禁用或安装位置不正确。

向导默认推荐风险最低的方案：优先保留用户已有内容，给新工具或工作流创建隔离的受管理副本，或在项目范围启用正确版本。只有用户明确选择“替换”时，才会替换由本应用管理的版本；从不删除或覆盖用户非受管理的原始文件。

每次修复都先生成并展示变更计划，再创建恢复点，最后由用户确认执行。结果显示“已修复”“仍需授权”或“无法自动修复”，并提供明确下一步。对于需要理解第三方脚本行为的冲突，应用只能解释和隔离，不能假装已经安全修复。

### 删除与更新管理

高级页支持“彻底删除 Skill/插件”。用户选择条目后，应用先扫描并列出该条目在本机的所有已知受管理副本、配置引用、关联工作流和即将失效的业务工具。用户必须逐项确认删除范围，并进行一次最终确认；默认不勾选任何关联项。

删除策略如下：

- 对应用管理的副本，删除源文件、受管理配置引用、缓存和本应用的目录记录。
- 对用户手动安装或项目自带的副本，只标示准确路径与影响；用户须额外确认才允许移除，且不会扩大到同名的其他目录。
- 删除前创建恢复点；删除后在恢复窗口内可一键恢复。用户选择“清除恢复点”后，才对应用管理的副本执行不可恢复的永久删除。
- 若删除会让已保存工作流不可运行，应用提供“保留工作流但标为缺失”“一起删除工作流”或“取消”三种明确选项。

应用定期扫描已安装、已导入和工作流锁定的 Skill/插件是否存在可用更新。更新策略以兼容性优先：

- 来源可信、版本兼容、未新增高风险权限的补丁更新可按用户开启的“自动更新”策略自动安装，并在更新历史中记录。
- 大版本更新、依赖变化、权限变化、来源变更或可能影响已保存工作流的更新，必须先显示影响与回滚点，再由用户确认。
- 工作流默认继续使用它锁定的版本；用户可以在工作流详情中选择“检查并升级”，通过预检后生成新的锁定版本。
- 无法验证来源、校验失败或更新规则不明确的项目只能提示，不能自动更新。

### 工作流库

工作流是用户可保存和复用的一套业务步骤，而不是单个 Skill。例如“道具客户提案”工作流可以串联灵感研究、概念设定、预算清单和 PPT 提案。

用户可以在工作流编辑器中选择任务步骤、输入输出、每步使用的工具，以及可选的默认提示词和素材目录。保存后，应用记录工作流定义和它要求的精确工具版本、依赖、权限及执行顺序。

用户可将工作流导出为可分享安装包。另一台电脑导入时，应用：

1. 读取工作流清单和锁定的依赖版本。
2. 扫描本机 Codex 与现有工具。
3. 检查缺失项、版本不符、冲突和需要重新登录的外部服务。
4. 生成安装或修复计划，由用户确认后安装全部可获取的 Skill/插件。
5. 完成验证后把工作流标为“可运行”；若有未满足条件则标为“需处理”，不误导用户直接运行。

工作流包不导出 API 密钥、登录令牌、用户私人文件或未获授权的第三方内容。导入后的外部账号连接必须由目标电脑的用户自行授权。

### 精选工作流推荐与本地部署

应用提供“推荐工作流”目录，面向不想自己搭建流程的用户。目录按职业和目标组织，例如道具设计师、演示文稿制作、短视频策划、数据分析和营销内容。用户搜索“做 PPT”时，除了本机已有工具，也能看到经过验证的成品工作流。

每个推荐工作流必须提供以下公开元数据：

- 业务目标、输入、输出、适用人群和示例结果。
- 作者/发布方、来源地址、发布日期、当前版本和更新记录。
- 所需 Codex 版本、Skill/插件/MCP 依赖、外部账号和权限风险。
- 已验证的操作系统、最近一次兼容性测试时间和测试状态。
- 一键部署前的完整安装清单，以及无法满足时的替代方案。

第一版只展示由工具箱团队或明确标为可信的发布方审核过的推荐工作流；不把未经审核的网络脚本自动列为“推荐”。社区工作流可以被搜索和导入，但必须显示为“未验证来源”，并走完整的导入、隔离和权限确认流程。

“一键部署到本机”不是静默安装：应用会下载或获取已锁定版本的工作流包，运行本机扫描和冲突预检，生成安装/修复计划，创建恢复点，取得用户确认后安装全部可获取依赖，并执行一次不含敏感数据的验证任务。验证成功才显示“已部署，可运行”；任一步失败则回滚由应用管理的变更并给出可理解的失败说明。

### 本机能力扫描

首次启动及用户手动触发时，扫描器执行：

1. 检查 Codex 是否存在且可调用；不存在时提供安装说明，不代替用户安装。
2. 发现全局、项目级和已安装插件带来的 Skills。
3. 读取名称、描述、路径、来源、版本（如有）和支持文件。
4. 标记同名项的优先级、生效版本、重复项和禁用/缺失项。
5. 对职业工具和自定义工具计算依赖状态：已满足、缺失、冲突或需要授权。

扫描默认只读。安装、启用、导入和删除必须由用户明确触发。

## 核心交互流程

```text
首次启动
  -> 扫描本机 Codex 环境
  -> 显示可用能力与缺失前置条件
  -> 选择职业工具箱（默认展示道具设计师）
  -> 选择业务任务
  -> 预检依赖与权限
  -> 用户确认安装/启用
  -> 调用本机 Codex 执行
  -> 展示进度、产物路径和失败建议
```

导入自定义工具：

```text
选择文件夹或 ZIP
  -> 解包到应用管理的隔离区
  -> 校验结构和清单
  -> 扫描声明依赖、脚本和权限提示
  -> 显示预览与冲突
  -> 用户确认启用
  -> 写入或链接到目标 Codex 范围
```

## 依赖和安全模型

工具包使用一个显式清单记录：工具 ID、版本、主 Skill、依赖项、来源、最低 Codex 要求、可选外部服务以及风险标签。

风险标签至少包括：联网、读取工作区、写入工作区、执行命令、外部账号访问。第一版只展示和确认这些标签；不声称能够完整审计任意第三方脚本。

安装前必须显示：将添加的项目、写入位置、来源、版本、已解析依赖和权限风险。每次从未信任来源导入时，用户必须再次确认。

推荐器在给出“立即运行”结论前，必须对方案执行冲突预检：

1. 主 Skill 和每项依赖是否存在且可发现。
2. 同名 Skill 是否被更高优先级版本覆盖。
3. 依赖是否声明不兼容版本或互斥外部服务。
4. 方案是否需要尚未授予的高风险权限。

预检结果分为“可运行”“需安装”“需授权”“存在冲突”“无法判定”。只有“可运行”的方案显示为一键执行；其余状态必须说明阻塞原因和可选修复动作。第一版的冲突判断仅基于显式清单、路径优先级和已知规则；对无法静态确定的第三方脚本，必须标记为“无法判定”，不能承诺绝不冲突。

回滚通过保存每次变更前的工具箱清单和受管理副本实现。第一版只回滚由本应用管理的内容，不改动用户已有的原始文件。

## 分享格式

导出的分享包采用 ZIP，包含：

- `toolbox.json`：工具箱元数据、版本与依赖声明。
- `tools/`：自定义 Skill 或插件的源文件。
- `README.md`：业务用途、安装说明、风险说明和支持范围。

工作流分享包在上述结构上增加：

- `workflow.json`：步骤、输入输出、默认值、执行顺序和依赖锁定。
- `lock.json`：所需 Skill/插件的来源、准确版本或内容标识、最低 Codex 要求及兼容规则。
- `assets/`：用户明确选择共享、且不含凭据的示例素材。

导入时不自动执行包内脚本；脚本是否可运行由结构校验和用户确认决定。

## 第一版技术划分

- 桌面壳：提供安装、职业工具箱和高级管理界面。
- 本地发现器：只读扫描 Codex 可发现位置和应用自管目录。
- 工具清单服务：维护职业工具到 Skill 依赖的映射与状态。
- 冲突修复服务：生成确定性冲突的变更计划、恢复点和回滚操作。
- 工作流服务：保存步骤、依赖锁定和分享包的导入/导出。
- 推荐目录服务：缓存审核通过的工作流元数据、按职业/任务搜索并提供部署清单。
- 本地部署服务：执行推荐工作流的下载、预检、受管理安装、验证与回滚。
- 更新服务：检查可信来源、评估兼容性、应用符合策略的更新并记录历史。
- 删除服务：生成精确删除清单、恢复点和受管理内容的永久清理。
- 导入/导出服务：校验、隔离、打包和受管理安装。
- Codex 适配器：检查本机 Codex、构造任务调用并收集执行结果。

这些模块仅通过清晰的数据模型通信；扫描器不负责安装，导入器不负责执行任务，Codex 适配器不决定业务工具的依赖。

## 验收标准

1. 在未安装 Codex、已安装但无 Skill、以及已有多个 Skill 的电脑上，应用能给出准确的状态和下一步。
2. 道具设计师工具箱的五项业务工具均能显示用途、依赖和状态。
3. 用户搜索“做 PPT”时，应用返回一个可解释的首选执行方案和至多两条替代方案，而不是 Skill 列表。
4. 推荐方案在执行前完成依赖与冲突预检，且不把“存在冲突”或“无法判定”的方案标为可直接运行。
5. 面对支持范围内的冲突，用户可查看推荐修复计划、创建恢复点、确认修复并回滚由应用管理的变更。
6. 用户能保存一个由多步业务任务组成的工作流，并查看其中锁定的依赖和权限。
7. 用户能导出一个工作流，在另一台电脑导入后获得完整的依赖预检、安装/修复计划和运行状态。
8. 工作流分享包不得包含 API 密钥、登录令牌或用户私人文件；目标电脑必须自行重新授权外部服务。
9. 用户搜索“做 PPT”等目标时，能看到经过审核的推荐工作流、部署要求和推荐理由。
10. 推荐工作流可在本地完成预检、安装、验证和回滚；只有验证成功后才标为可运行。
11. 用户能预览一个 Skill/插件的精确删除范围、受影响工作流和恢复方案，再选择永久删除受管理内容。
12. 自动更新只应用可信且兼容的低风险更新；其他更新必须展示影响并要求确认。
13. 已保存工作流在默认情况下保持锁定版本，并可由用户主动检查并升级。
14. 用户能导入一个合法 Skill 或插件目录/ZIP，看到依赖预检后再决定是否启用。
15. 用户能导出一个自定义工具并在另一台电脑导入；导入后仍经过预检与确认。
16. 重复或被覆盖的本地 Skill 在高级页清楚标示，不会被应用静默删除或改写。
17. 所有会写入、联网、执行命令或访问外部账号的操作均有明确提示和用户确认。

## 验证策略

- 为路径发现、清单解析、依赖解析、意图匹配、冲突预检、修复计划、删除范围、更新兼容性、工作流锁定、推荐目录过滤、部署计划和 ZIP 校验编写单元测试。
- 用临时目录模拟无 Codex、单层 Skill、同名覆盖、缺失依赖、互斥依赖、可回滚修复、版本漂移、补丁更新、破坏性更新、永久删除、推荐工作流部署失败和损坏 ZIP。
- 人工验收安装后首启、职业工具展示、任务搜索、推荐理由、推荐工作流本地部署、冲突修复、更新历史、删除与恢复、工作流保存和跨电脑导入、导入预检、启用确认和导出再导入。
